# SQL Lab expansion verification

Tested 14 November 2026. Scope: **48 new exercises, 60 total**. Feature branch: `feature/sql-learning-path-60`. Built on iPhone header commit `0d172fd2d3e73f74711154b601273d6426cf51b5`; main/live deployment is not modified.

## Automated SQL coverage

| Check | Exact coverage |
| --- | --- |
| Canonical solution execution | 60 exercises × 4 dataset variants × 6 fixtures × 2 engines = **2,880** fixture executions |
| Original 12 result regression | 12 exercises × 4 variants × original 3 fixtures × 2 engines = **288** comparisons with saved main-branch result hashes |
| Original contracts | SQL, expected columns, ordering flags and starters for all 12, across 4 variants in both engines |
| Deliberately wrong answers | All 48 new exercises have a logical-error query; each is rejected on at least one tested dataset in each engine |
| Independent result oracles | 7 JavaScript calculations × 4 variants × 6 fixtures × 2 engines = **336** comparisons |

Independent oracles verify inclusive amount thresholds, inclusive intervals, half-open date intervals, row counts, nullable counts, zero-preserving account activity and all tied regional debit peaks. Reference SQL execution alone is not presented as an independent correctness oracle. Wrong queries are tried across all 24 datasets per engine; they need not fail on every dataset, because some mistakes only appear at boundaries or with ties/fanout.

For all 60 exercises, each variant's visible result frozen as a literal answer is rejected by at least one hidden fixture in both engines: **480 exercise/variant/engine cases**. Hidden data includes changed region/channel categories so even DISTINCT region lists cannot pass as fixed literals. The original three seed fixtures remain unchanged.

The grader additionally rejects wrong result columns, missing rows and duplicate rows; required ordering is tested by reversing nontrivial ordered results. Read-only and single-statement restrictions are tested on every fixture. No SQL syntax pattern is required for a correct result.

## Browser and user-flow coverage

Chromium and WebKit, using Playwright 1.65.0:

| Check | Coverage |
| --- | --- |
| Full application grading offline | All 60 solutions through the actual Worker/UI in each engine; each run checks practice plus five additional fixtures |
| User-flow records | **130** recorded checks, including the 120 exercise runs, hidden-only log-fanout rejection, timeout/recovery, coaching gate, saved-state checks and cold offline file startup |
| Saved state | Draft/progress/assisted reload, separate dataset drafts, old exercise index 9 and original completion keys retained |
| Coaching and inspection | No immediate worked solution; unsuccessful attempt plus two hint stages; assisted marker; inspection never changes completion |
| Runtime safety | Infinite recursive aggregate cancelled after five seconds, followed by a successful query; no uncaught page errors or external requests |

The loop-level SQL matrix uses the same bundled SQLite engine directly to avoid repeatedly loading its code. Full UI checks separately exercise Worker messaging, hidden-fixture execution and result feedback.

## Mobile checks

**40 layout cases:** 3 exercise screens × 6 widths × 2 engines = 36, plus portrait/landscape safe-area substitutions in both engines = 4.

Widths: 320, 375, **390 × 720**, 430, landscape 844 × 390 and desktop 1280. Checks cover page overflow, solid `#281c31` header, no backdrop blur, separated brand/navigation, content below the header and scrolling with the header in normal document flow. Tables remain independently horizontally scrollable. The SQL editor uses 16px text.

Safe areas were simulated by substituting CSS environment values: 59px top/34px bottom for portrait and 59px side insets for landscape. The header's top inset is applied once. Screenshots are generated by the suite for beginner and advanced exercises in both engines.

## Limits and remaining device checks

1. **No physical iPhone testing.** WebKit on Windows is browser automation, not iOS Safari/Chrome. Real keyboard resizing, Dynamic Island geometry and Add to Home Screen launch/status-bar behavior remain unverified. Chromium's standalone display-mode emulation did not activate in this environment; this probe is recorded separately and is not counted as a passing layout case.
2. **Offline means the downloaded HTML.** Cold local-file startup and query execution passed with the network disabled in both engines. Hosted first visits still require internet; no hosted offline cache or installable PWA behavior was added.
3. **Finite fixtures.** Passing six fixtures does not prove arbitrary-data correctness. The schema is intentionally limited to accounts, transactions and logs; amounts use whole AUD and all data is synthetic. These exercises do not model a production ledger or operational policy.
4. **Storage remains local.** Browser storage availability and quotas vary; moving files/origins or changing browser/device may separate saved state. There is no cross-device synchronization.

## Reproduce

Run the commands in [README.md](README.md). Detailed results and screenshots are written to `test-results/verification.json` and `test-results/*-beginner.png` / `*-advanced.png`. These generated files are ignored by Git. No merge or publication is part of the test process.
